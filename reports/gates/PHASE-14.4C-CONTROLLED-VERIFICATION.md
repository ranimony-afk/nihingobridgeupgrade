## 7. Environment disclosures (verification-harness facts)

1. **Disposable DB engine:** PGlite (`@electric-sql/pglite` + `pglite-server`) on
   `127.0.0.1:5432`, data dir `/tmp/disposable-pg-g0`; role `nihongo`, database `app_db`;
   schema via `drizzle-kit push`. Only disposable targets were touched.
2. **TCP_NODELAY harness swap:** `pglite-server` leaves Nagle enabled; measured query
   round-trip was **44 ms** (delayed-ACK interaction), which made the full JMdict load
   take hours. A `/tmp`-only launcher (byte-equivalent to `scripts/run-disposable-pg.ts`
   plus `socket.setNoDelay(true)` on accepted connections; **no workspace file modified**)
   reduced round-trip to **0.4 ms**. Same engine, same data dir, same wire protocol.
3. **JMdict full load (§14G requirement):** `scripts/provision-jmdict-ci.ts` (pinned
   identity, SHA `a9be8a98…`, 115,331,197 B, 206,717 entries) then
   `scripts/ingest-full-jmdict.ts --authorize-full-ingestion` on the disposable target.
   The PGlite bridge reports `current_database()`/`current_user` as `postgres`, so that
   run declared `NIHONGO_DB_EXPECTED_DATABASE=postgres` for the loader's identity probe
   (still fully classified `DISPOSABLE`: loopback + exact operator-named database).
   The loader was stopped/resumed under operator control three times (checkpoint
   `data/jmdict-checkpoint.json`, uncommitted) while diagnosing the harness latency; its
   built-in idempotency pass healed the 846 rows those abnormal terminations left behind
   (`idempotencyRun2.inserted=846`) and the **final state is exactly 206,747**
   (= 206,717 + 30), independently SQL-verified and asserted by canonical test #12.
   The loader's `isIdempotent:false` flag refers to that healing pass and is disclosed
   as such; the contract state itself is complete and was re-verified idempotent by the
   KANJIDIC2 run 2 and canonical #13.
4. `NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt` for provisioner TLS;
