# Japanese Upstream Resource Register — Kanji MindTree

**Research snapshot:** 2026-10-29 (UTC metadata as returned by GitHub API)
**Scope:** source selection for the locally usable Kanji MindTree vertical slice. This is a provenance and engineering register, not legal advice or a representation of legal clearance.

## Decision summary

The implementation retains 33 first-party study-record rows and expands the bounded learning slice to 100 exact kanji using 100 pinned KanjiVG glyph files and a separate 100-record KANJIDIC2 facts artifact. The artifacts remain distinct: KanjiVG supplies only path geometry and literal source-group annotations; KANJIDIC2 supplies English meanings, Japanese On/Kun readings, grade, stroke count, and classical-radical index number; first-party study records supply examples, radical selections, and 31 remaining draft memory cues. M4 separately records 44 AI-assisted candidates in an unpublished overlay and leaves 25 supported characters without mnemonic records. No full upstream corpus is committed.

M3 resolved the KANJIDIC2 license discrepancy against EDRDG's current official general dictionary license page, fetched 2026-10-29: it states CC BY-SA 4.0, applies to KANJIDIC2 and derived files, and replaces prior license statements. The old in-repository KANJIDIC2 acquisition contract/manifest still says CC BY-SA 3.0; it was not rewritten because that would alter a historical ETL gate. The M3 artifact therefore records the current source-specific CC BY-SA 4.0 notice and its URL, with attribution/share-alike conditions and no claim of legal clearance. English meanings and Japanese readings only are selected; non-English meanings and separately credited code systems are omitted. The official notice also requires a regular update procedure; this snapshot has a documented manual refresh path, but operational cadence remains an owner follow-up.

No JMdict, Tatoeba, CJKVI IDS, CHISE, WaniKani, Kanji Alive, or third-party mnemonic content is copied. Existing dictionary, editorial, Tatoeba, and SRS gates remain authoritative.

## Primary and authoritative source boundaries

- **Unicode:** the slice uses exact Unicode scalar/code-point identities and does not import Unicode property tables or claim Unicode defines semantic decomposition. No Unicode data artifact is copied.
- **KANJIDIC2 / EDRDG:** M3 uses only the pinned 2023-08 KANJIDIC2 XML identity recorded above, from which it selects English meanings, Japanese On/Kun readings, education grade, stroke count, and the classical radical index number for 100 glyphs. It excludes non-English meanings and separately credited SKIP, Pinyin, Korean, and other code/reading material. Current EDRDG terms say CC BY-SA 4.0 and replace earlier notices; the unchanged local ETL registry/contract still records CC BY-SA 3.0 as historical gate metadata, so the source-specific MindTree artifact and NOTICE carry CC BY-SA 4.0. Follow the official regular-update requirement: periodically check the latest official source/archive snapshot, re-pin the immutable blob and XML hash/version, regenerate, test, and refresh attribution; the current implementation documents this manual procedure but does not automate the cadence.
- **JMdict / EDRDG / Tatoeba:** no new lexical rows or example sentences are acquired here. Continue using the established NihongoBridge lexical integration and Tatoeba provenance/quality gates.
- **CHISE:** CJKVI README refers to `https://www.chise.org/`; no CHISE artifacts were downloaded. GitHub repository search did not identify a source repository with a clear license; treat CHISE-derived IDS as restricted until the applicable upstream terms are independently verified.
- **WaniKani:** do not copy proprietary meanings, radicals, mnemonics, API records, or illustrations. A public client's open-source license does not license WaniKani content.

## Reproducibility and compliance checklist

1. Pin the KanjiVG tag/commit and archive URL; verify the archive digest before extracting the exact 100 selected primary SVGs. Preserve each raw file SHA-256 and regenerate the source graph deterministically.
2. Pin the KANJIDIC2 archive commit/blob and XML identity; check the official EDRDG license notice and release metadata. The M3 generator uses the existing fail-closed acquisition contract, parses the verified XML, and writes only the 100-character English/Japanese facts subset.
3. Keep the KanjiVG structure artifact (CC BY-SA 3.0) and KANJIDIC2 fact artifact (CC BY-SA 4.0) separate, with distinct attribution, source version, hashes, transformation note, and share-alike notice.
4. Keep first-party learner content, JMdict/Tatoeba data, dictionary radical-index numbers, visual annotations, derived relationships, editorial interpretations, mnemonics, and the M4 AI candidate overlay in distinct lanes; never promote the AI-origin records.
5. For the official EDRDG regular-update requirement, schedule a manual monthly source check; when upstream bytes or terms change, update immutable pins, regenerate both matching slices, verify hashes/counts, run focused tests, and revise notices/register/report. No automated monthly job is in this M3 slice.
6. Re-run license and provenance checks on every source update. This register records observed declarations and engineering controls; it is not legal advice or a legal clearance opinion.
